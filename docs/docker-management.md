# Web Docker management backend

The standalone web view uses `POST /api/docker` with JSON. When web authentication is enabled, a live web-auth session is required; when disabled, no login is required. **With authentication disabled, anyone who can reach the viewer has trusted host Docker and discovered-file control.** Supply a same-origin Origin or Referer (the existing same-origin policy also supports `Sec-Fetch-Site: same-origin`). Responses are JSON with `Cache-Control: no-store`. This endpoint is independent of viewer projects and is not available through desktop IPC.

- `{ "action": "list" }` returns `{ "containers": [{ "id", "name", "state", "status" }] }` for all existing containers.
- `{ "action": "start" | "stop" | "restart", "containerId": "<id>" }` returns `{ "ok": true }`.
- `{ "action": "remove", "containerId": "<id>", "confirmed": true }` removes a stopped container only, without force or volume deletion. The UI must explicitly confirm before sending it.
- `{ "action": "updateImage", "containerId": "<id>", "confirmed": true }` uses the selected container's Compose project, service, working directory and original configuration files. It pulls only that service, then recreates it with `up -d --no-deps --force-recreate`. All replicas of that service may be recreated; no orphan removal or project-wide update is requested. Standalone containers and inaccessible metadata are unsupported. If recreation fails after download, the error reports partial failure; no rollback is attempted. Compose uses the original working directory and its environment, which may differ from the original deployment. Each operation has a 15-minute timeout and retains at most 256 KiB of combined output.
- `{ "action": "logs", "containerId": "<id>" }` returns `{ "stdout", "stderr" }`. Logs use the last 500 lines; combined Docker output is limited to 256 KiB, with an explicit error if exceeded.

- `{ "action": "files", "containerId": "<id>" }` returns `{ "files": [{ "path", "kind", "identity" }] }` from the selected container's Compose labels. `kind` is `yaml` or `env`.
- `{ "action": "readFile", "containerId": "<id>", "file": <discovered file> }` returns `{ "content", "version" }`. Send the unchanged file descriptor back; paths alone are not authority.
- `{ "action": "saveFile", "containerId": "<id>", "file": <discovered file>, "version": "<version>", "content": "<raw text>" }` returns `{ "ok": true }`. Rediscover and reopen after a save or conflict. Save validates first and never applies or restarts containers.

Validation stages discovered Compose files and one sibling `.env` together, with explicit Compose inputs. Multiple sibling `.env` files or duplicate Compose basenames cannot be staged and return an error. External relative references can fail or resolve differently in staging; successful validation does not prove deployment readiness. Compose may access auxiliary files with the viewer's trusted host-administrator authority. Originals are not overwritten during validation.

Simultaneous saves to the same path in this server process are rejected; reopen after a conflict. External changes are checked immediately before atomic rename, but a separate process can still edit the file between that check and rename. Symbolic-link configuration files are unavailable. Compose validation diagnostics are returned only to the requester, without server logging or shared broadcasts; they can contain sensitive values, so handle them accordingly. Control characters are removed and diagnostics are limited to 4096 characters.

IDs must be lowercase hexadecimal Docker IDs of 12–64 characters. Use IDs returned by list, not names. No create action is supported. Failures return a non-200 status and `{ "error": "..." }`; do not display them as empty lists. Requests are limited to 2 MiB, file contents to 256 KiB, and Docker commands other than Compose update operations time out after 30 seconds.
