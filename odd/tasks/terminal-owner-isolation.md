## Specs

### S1 — Resume the same project process [behavior]

> "si digamos no es el fin en si de solo retormarla para terminalar sino retomar el proceso de nuevo y no quede bloqueado"
> "hagamoslo sencillo, guardemos el set de pid asociados a un proyecto, para retomarlos, no necesito tanta seguridad porque es el entorno del usuario con que aseguremos la conexion del webbridge me basta, porque quiero un set de pid porque luego vamos a integrar tabs para la terminal y poder mas de una terminal en el proyecto"

- Authorized WebBridge clients MUST share project terminal sessions regardless of login identity. Reopening the same canonical directory MUST reattach to its live process with replay, rather than spawn another shell.
- Project collections MUST retain live session objects (ID, PID, PTY), not PID-only metadata. Existing open command MUST select the live default; future tabs and new creation APIs are out of scope.
- Closing a session MUST remove that session from both indexes; an empty project collection MUST be removed. Dead-session replacement MUST clean stale indexes without affecting other projects.
- **S1.1** Given an authenticated web client opens a project, when another authenticated web identity opens the same canonical directory after a frontend reopen, then both obtain the same live ID/PID, buffered output, and can use get/list/poll/write/resize/close through authorized HTTP requests.
- **S1.2** Given sessions in distinct projects, when one is closed and reopened or exits and is reopened, then it receives a new session while the other project's original live session remains accessible.

### S2 — Keep WebBridge authorization [behavior]

> "con que aseguremos la conexion del webbridge me basta"

- Existing origin/authentication/verified-loopback checks MUST remain the terminal authorization boundary for every HTTP terminal command. Internal dispatcher/manager calls are not public authentication boundaries.
- Unauthorized attempts MUST NOT operate on a live terminal or mutate its process/dimensions; terminal output MUST NOT be broadcast over shared SSE.
- **S2.1** Given a live project terminal, when unauthorized, invalid-origin, or non-loopback unauthenticated HTTP clients attempt terminal operations, then existing HTTP status/error responses remain and authorized clients still observe the same usable session and dimensions. Existing loopback access with authentication disabled remains functional.
